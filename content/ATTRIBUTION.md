### Exception: MPL-2.0 crates pulled in by Tauri
Five transitive dependencies of **Tauri 2** are licensed under the Mozilla Public License 2.0, which is weak (file-level) copyleft rather than permissive:

`cssparser`, `cssparser-macros`, `selectors`, `dtoa-short`, `option-ext`

- They are reached only through `tauri` / `tauri-utils` / `dirs`, so they are linked only into the desktop shell (`terragen-desktop`), never into the engine crates, the CLI or the web build.
- They are used unmodified. MPL-2.0 permits this in a closed-source product; its obligations apply to modifications of those files, and their source is published on crates.io.
- `deny.toml` lists each crate as an individual exception. MPL-2.0 is **not** on the general allow-list, so any new MPL dependency fails the audit.

**Accepted by the project owner on 2026-11-10.** The exception cannot be avoided while Tauri 2 is the desktop shell; it covers these five crates only.

### Exception: MPL-2.0 crates of Symphonia (audio decoding, `SRC-AUDIO`)
**Symphonia** 0.5.5 (<https://github.com/pdeljanov/Symphonia>, Philip Deljanov and contributors) decodes MP3, FLAC and Ogg Vorbis files at import (`tg-sources::codec`, M6 step 26). It is licensed under the **Mozilla Public License 2.0** (checked: the repository's `LICENSE` and each crate's licence field on crates.io, 2026-11-17), weak (file-level) copyleft. Eight crates are linked, built with `default-features = false` and the features `mp3`, `flac`, `ogg` and `vorbis` (so no WAV, PCM, ADPCM or MKV code):

`symphonia`, `symphonia-core`, `symphonia-metadata`, `symphonia-utils-xiph`, `symphonia-bundle-mp3`, `symphonia-bundle-flac`, `symphonia-format-ogg`, `symphonia-codec-vorbis`

- They are used unmodified, as libraries; MPL-2.0 permits that in a closed-source product, and its obligations attach to modifications of those files, whose source is published on crates.io and GitHub.
- `deny.toml` lists each crate as an individual exception (never MPL-2.0 in `allow`), so any other MPL dependency still fails the audit.
- They build for the engine's WASM target too (`cargo xtask wasm`), so a browser decodes in the engine, never with the browser's own decoder.
- A WAV file is read by a reader of our own (`tg-sources::audio`), with no dependency.

**Accepted by the project owner on 2026-11-16** (`docs/07-M6-PLAN.md` §4.2, second answers, item 4).

### ISC (on the allow-list since 2026-11-11)
ISC is permissive (the 2-clause BSD licence in simpler words, no copyleft), so it is within the rule and the project owner added it to the allow-list in `deny.toml` on 2026-11-11 rather than naming crates. Today the one ISC crate is `libloading`, which wgpu's native backends use to load the Vulkan, Direct3D 12 and EGL libraries at run time. It is linked only where `tg-render`'s `gpu` feature is enabled: native builds, never the WASM engine. The MPL-2.0 crates above stay named individually.

### Ignored advisories
Four "unmaintained" notices (not vulnerabilities) are ignored in `deny.toml` because they come from dependencies TerraGen does not choose: `paste` (via `tauri-specta`, RUSTSEC-2024-0436) and `proc-macro-error` (via Tauri's GTK3 backend on Linux, RUSTSEC-2024-0370). Revisit them when Tauri or tauri-specta is upgraded. Two more, added on 2026-11-15 with `krilla` (`PUB-4`) and **accepted by the project owner the same day**: `rustybuzz` (RUSTSEC-2026-0206) and `ttf-parser` under it (RUSTSEC-2026-0192), both unmaintained notices, not vulnerabilities; krilla shapes text with the one and the other parses fonts. Revisit when krilla moves to `skrifa`/`harfrust`.

## The About dialog and the installers (`REL-1`, M6 step 34)
- **The notices are generated, never hand-kept.** `cargo xtask notices` (our own code in `xtask/src/notices.rs`; no new dependency, so no new licence) writes `app/src/generated/notices.json`, which the About dialog shows: this file, the licence files of every Rust crate linked into the desktop shell, the engine's WASM module and the canvas's (normal dependencies only, all platforms; read from the sources cargo keeps, including the QuickJS-NG notice vendored in `rquickjs-sys`), of every npm package that ships in the app (`pnpm licenses list --prod`), and of the bundled fonts. A crate that ships no licence file is listed with its SPDX licence, its authors and its source, and with Apache-2.0's or MPL-2.0's standard text when its licence names one. `cargo xtask notices --check` (a step of `cargo xtask ci`) fails when it is out of date. Test and build tools (axe-core, Playwright, Vitest, `tauri-build`) are not in the bundle and are not listed. A new font folder in `fonts/` fails the task until its licence file is named there.
- **NSIS** (the Windows installer's maker, fetched by Tauri's bundler on first use into `%LOCALAPPDATA%	auri`; a build tool, not linked into TerraGen): zlib/libpng licence, its bzip2 module under the bzip2 licence, its LZMA module under the Common Public License 1.0 **with an exception for code linked to the module** (read 2026-11-17 at <https://nsis.sourceforge.io/License>). The installer holds NSIS's stub and so those modules; CPL-1.0 is not on the `cargo deny` allow-list, which only checks Rust crates. Left for the owner to confirm (docs/PROGRESS.md, step 34).
- **WebView2**: the Windows installer is Tauri's default and may fetch Microsoft's WebView2 bootstrapper at install time on a PC without it (Windows 11 has it); the app itself makes no network call.

## Algorithms and references
Implemented from the cited public sources, with citations in the doc comments:

- Bézier flattening: Wang's formula, from R. Goldman, *Pyramid Algorithms*, Morgan Kaufmann 2003, §5.6.3 (`tg-geom`).
- OKLab: B. Ottosson, "A perceptual color space for image processing", 2020 (`tg-core`).
- ChaCha: D. J. Bernstein, "ChaCha, a variant of Salsa20", 2008; SplitMix64: Steele, Lea and Flood, OOPSLA 2014; FNV-1a: Fowler, Noll and Vo (`tg-rand`).
- Unbiased bounded integers: D. Lemire, ACM TOMACS 29(1), 2019; normal deviates: Box and Muller, 1958 (`tg-rand`).
- SVG 1.1 (W3C); Inkscape layer attributes; AxiDraw layer-name conventions (`tg-io`).
- Radix-2 fast Fourier transform: J. W. Cooley and J. W. Tukey, "An algorithm for the machine calculation of complex Fourier series", Mathematics of Computation 19, 1965; the short-time Fourier transform and its Hann window: D. Gabor, 1946, and J. B. Allen, IEEE Trans. ASSP 25, 1977 (`tg-gen::audio`). The Lissajous figure: J. A. Lissajous, 1857.
- Passes on a 3D model (`tg-gen::mesh`, M6 step F14): the choice of passes (isolines of height, depth and distance; flat cast shadows with a ground shadow; curvature strokes; a multiview sheet) follows the Volume workspace of **vectorio** by Raul Lorenzo (MIT, <https://github.com/gdx54/vectorio>, `docs/volumen/` read on 2026-11-18). Ideas only: its documentation was read as a description and no code was copied; each pass is implemented here from the papers. Cast shadows: A. Appel, "Some techniques for shading machine renderings of solids", AFIPS Spring Joint Computer Conference, 1968. Isolines on triangles: the simplex case of W. E. Lorensen and H. E. Cline, "Marching cubes", SIGGRAPH 1987. Curvature strokes: A. Girshick, V. Interrante, S. Haker and T. Lemoine, "Line direction matters", NPAR 2000; S. Rusinkiewicz, "Estimating curvatures and their derivatives on triangle meshes", 3DPVT 2004; B. Jobard and W. Lefer, "Creating evenly-spaced streamlines of arbitrary density", 1997. Multiview sheet: third-angle projection as in ISO 5456-2:1996.
- Interleaved sampling: A. Keller and W. Heidrich, "Interleaved Sampling", Eurographics Workshop on Rendering, 2001 (`tg-render`, GPU coverage samples).
- FluidNC HTTP request formats (firmware probe, `/command`, `/upload`, `/files`, `$SD/Run`, the post-upload size check): behaviour mirrors terraForge by Mark Benson (MIT, <https://github.com/theworkisthework/terraForge>, `src/machine/fluidnc.ts` at commit `dd0e310`). Re-implemented in Rust from reading that client; no code was copied (`tg-machine::fluidnc`).

## Models
Each model is pinned in `models/manifest.json` by the M4 step that first uses it, recorded here with its licence as read at the authors' own source, and checked by `cargo xtask models-gate` (permissive, `commercial: true`, within 200 MB desktop / 100 MB browser). No non-commercial model may ship. **The desktop installer carries every model below** (`REL-1`, M6 step F16, the owner's answer of 2026-11-18): the release workflow runs `cargo xtask fetch-models`, which downloads each desktop model from its pinned URL, refuses any whose size or sha256 differs, and leaves it in `desktop/src-tauri/resources/models/` for Tauri to ship; the app checks each again against the manifest when it starts and installs it into its store. Redistribution rests on each licence below (Apache-2.0 for Depth Anything V2 Small, U²-Net-P and SAM 2.1; MIT for YuNet and TEED): the licence is named with each model and its text is at the source recorded for it (the manifest's `licence_source`), and the Apache-2.0 text is the one the About dialog already carries for the Apache-licensed packages. The sources recorded here name no separate NOTICE file for any of the six; if one is found at a source later, it is kept beside the model in the installer. The web build is unchanged: it downloads a model once, with consent, from the same pinned URL. A build made without `fetch-models` (every developer's) carries none, and a model added to the manifest later is fetched with `models.fetch`. Shipping a model unlocks nothing: the ML styles stay Pro.
